# 否定文リライト判定 Webアプリ 設計書

## 1. 背景・目的

`input/04_natural.csv` には、否定文（`original_sentence`）を焦点（focus）に関する言語処理ルールで書き換えた文（`rewritten_sentence`）が72件収録されている。各行にはリライトの根拠となる詳細な言語情報（否定辞・焦点範囲・書き換えルールIDなど）が付随している。

現状はCSVを直接開いて目視確認しており、以下がやりづらい：

- 1セルに長文が入っており、original / rewritten の比較がしにくい
- 判定結果（OK/NG）を記録する場所がない
- 72件の進捗管理ができない

そこで、1件ずつ original_sentence と rewritten_sentence を見比べながら、

1. **文意が変わっていないか**（意味保持）
2. **文が自然か**（自然性）
3. **否定範囲が変わっているか**（OK＝変わっている、NG＝変わっていない）

を判定し、結果を記録できるローカルWebアプリを作る。

## 2. 利用者・利用形態

- 利用者は自分一人（判定者名の管理は行わない）
- ローカルPC上でサーバーを起動し、ブラウザ（`http://127.0.0.1:5000`）からアクセスして使う
- 多人数同時アクセスは想定しない（排他制御は簡易でよい）

## 3. 全体構成

```
[Browser]  <---- HTTP (JSON API) ---->  [Flask App] <----> [input/04_natural.csv]
  (SPA風のHTML/CSS/JS)                   (Python)              (読み書き対象)
```

- バックエンド: Python + Flask（軽量・単一プロセスで完結）
- データ保持: 起動時にCSV全体を `pandas.DataFrame` としてメモリに読み込み、判定結果を都度メモリ更新 → CSVへ書き戻す
- フロントエンド: 素のHTML/CSS/JS（ビルド不要、フレームワーク導入は行わない）
- 永続化: **元CSV（`input/04_natural.csv`）に判定結果の列を追加して直接保存**する

## 4. データ設計

### 4.1 主キー

`instance_id`（例: `PN1a_00002__31__5430__5360`）を一意キーとして使用する。72行すべてでユニークであることを確認済み。

### 4.2 追加する列

`input/04_natural.csv` の末尾に以下の列を追加する（既存55列は変更しない）。

| 列名 | 型 | 説明 |
|---|---|---|
| `meaning_preserved` | `OK` / `NG` / 空 | 文意が変わっていないか。空＝未判定 |
| `naturalness` | `OK` / `NG` / 空 | 文が自然か。空＝未判定 |
| `negation_scope` | `OK` / `NG` / 空 | 否定範囲が変わっているか。OK＝変わっている、NG＝変わっていない、空＝未判定 |
| `review_comment` | 文字列 | 任意コメント（判定理由・気になった点など） |
| `reviewed_at` | ISO8601日時文字列 | 最終更新日時（保存の都度上書き） |

- 「保留・要検討」のような中間状態は設けず、判定に迷う場合は `NG` にした上でコメントに理由を書く運用とする（後で見直しやすいように）。
- 既存の `negation_review_status` / `span_review_status` などの列とは独立管理し、混同しない。
- 3項目すべての判定で判定済みとする。旧CSVは既存の評価・コメントを保持し、新項目を空欄として読み込む。不足する列は次の保存時に末尾へ追加する。

### 4.3 保存方式・安全対策

- 1件判定するたびに **サーバー側で即時保存**（自動保存。明示的な保存ボタンは設けない）。
- 書き戻し時は以下の手順でデータ消失を防ぐ：
  1. 書き込み前に `input/04_natural.csv` を `input/.backup/04_natural_YYYYMMDD_HHMMSS.csv` にコピー（アプリ起動後の初回保存時、および任意間隔で世代管理。直近N世代のみ保持）
  2. 一時ファイル（例 `04_natural.csv.tmp`）に全内容を書き出してから `os.replace` で本ファイルに置き換える（アトミックな置換で書き込み途中破損を防止）
  3. CSVは元ファイルと同じ `utf-8-sig` エンコーディング・改行を含むフィールドはダブルクォートで保持（`pandas.to_csv` のデフォルト動作に準拠）

## 5. 画面設計

### 5.1 画面構成

1画面のSPA。上部に進捗、中央に判定カード、下部にナビゲーションを配置する「1件ずつ表示」形式とする（72件を一覧テーブルで並べると長文比較がしづらいため）。

```
┌───────────────────────────────────────────────┐
│ 進捗: 23 / 72 判定済み  [====------------]      │
│ フィルタ: [すべて / 未判定 / 意味NG / 不自然 / NG全部] │
├───────────────────────────────────────────────┤
│ #23  instance_id: PN1a_00002__52__10470__10360  │
│                                                  │
│ 【original】                                     │
│  また、家庭と学校の不干渉が徹底している欧米では、    │
│  家庭訪問は基本的に「ない」という。                  │
│                                                  │
│ 【rewritten】（差分ハイライト表示）                  │
│  また、家庭と学校の不干渉が徹底している欧米以外の、    │
│  ある文化圏では、家庭訪問の慣行が基本的にあるという。  │
│                                                  │
│ ▶ 参考情報を表示（開閉可能）                        │
│    focus_surface: 欧米 / negation_surface: ない   │
│    rewrite_rationale: LLM生成 (model=...)         │
│                                                  │
│ 文意が変わっていないか？   [ OK ]  [ NG ]           │
│ 文が自然か？             [ OK ]  [ NG ]           │
│ 否定範囲が変わっているか？ [ OK ]  [ NG ]           │
│ コメント: [__________________________]           │
├───────────────────────────────────────────────┤
│ [← 前へ]   [未判定へジャンプ]   [次へ →]           │
└───────────────────────────────────────────────┘
```

### 5.2 主な挙動

- **差分ハイライト**: `original_sentence` と `rewritten_sentence` を文字単位で差分比較し（Python `difflib.SequenceMatcher` の結果をAPIレスポンスに含める）、削除箇所は打消線、追加箇所は下線・色付けで表示する。文意判定の助けとする。
- **参考情報の折りたたみ表示**: 判定の助けになる列（`focus_surface`, `negation_surface`, `abstract_expression`, `except_prefix`, `rewrite_rationale`, `negation_note` など）をデフォルト非表示にし、必要なとき展開できるようにする。全55列を出す必要はない。
  - **全行で値が同じ列は表示しない**。サーバー起動時にCSVを読み込んだ際、各列のユニーク値数を調べ、値が1種類しかない列（＝どの行を見ても同じ情報しか持たない列）は参考情報の候補から自動的に除外する。列名をハードコードで除外リスト化すると、CSVの内容が変わった時に追従できず不整合が起きるため、**起動時の動的判定**とする。
  - 現時点（`04_natural.csv` 72行）で全行同一となり除外される列: `span_method`, `span_review_status`, `span_reason`, `negation_decision_type`, `negation_conversion_status`, `negation_review_status`, `negation_confidence`, `negation_forward_rule`, `abstraction_rule_id`, `abstraction_review_status`, `rewrite_rule_id`（参考情報として意味を持つのは主に行ごとに値が異なる列のみ）
  - `GET /api/items/<instance_id>` のレスポンスに含める参考情報フィールド一覧は、この動的フィルタ後のものとする（6章のAPI設計を参照）
- **OK/NGボタン**: クリックした瞬間に該当項目を確定・自動保存（保存中はボタンにローディング表示、完了後トースト通知）。選択済みのボタンはハイライトし、再クリックで選び直せる。
- **キーボードショートカット**: `1`=意味OK, `2`=意味NG, `3`=自然OK, `4`=自然NG, `5`=否定範囲OK, `6`=否定範囲NG, `→`=次へ, `←`=前へ。
- **ナビゲーション**: 3項目の判定が揃ったとき自動で次の未判定行へ進むオプションを持たせる（設定でON/OFF可）。
- **フィルタ**: すべて / 未判定のみ / 意味NGのみ / 不自然のみ / 否定範囲NGのみ / いずれかNG、で絞り込み、件数をリアルタイム表示。
- **完了表示**: 72件すべて判定済みになったら進捗バー付近に完了メッセージを表示。

## 6. API設計

すべてJSON。ベースパス `/api`。

| メソッド | パス | 説明 |
|---|---|---|
| GET | `/api/items` | 全72件の一覧を返す（フィルタ用に判定状況を含む軽量情報） |
| GET | `/api/items/<instance_id>` | 1件の詳細（original/rewritten/差分/参考情報/現在の判定値）を返す。参考情報は全行で値が同一の列を除いたもの（5.2節参照）に絞って返す |
| PUT | `/api/items/<instance_id>/review` | 判定結果を保存。body: `{meaning_preserved?, naturalness?, negation_scope?, review_comment?}`（部分更新可）。保存後、更新済みレコードとCSV書き込み結果を返す |
| GET | `/api/progress` | 判定済み件数・NG件数などのサマリを返す |

- サーバー起動時にCSVを読み込み、以降はメモリ上の `DataFrame` を正とする。`PUT` のたびにメモリを更新し、即座にCSVへ書き戻す（5.1の安全対策に従う）。
- 例外処理: 存在しない `instance_id` は404、不正な値（`OK`/`NG`/空以外）は400を返す。

## 8. 非機能要件

- 文字コード: 入出力とも `utf-8-sig` を維持し、Excel等で開いた際も文字化けしないようにする。
- CSV内の改行・カンマを含むフィールドはこれまで通りダブルクォートで保持されること（既存ファイルの形式を踏襲）。
- 想定データ規模は72件程度であり、パフォーマンス要件は特にない（全件メモリ保持で十分）。
- ローカル利用専用のため、認証機能は設けない（`127.0.0.1` バインドのみで外部公開しない）。
